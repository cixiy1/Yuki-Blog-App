null` 时**才自动套这段（写死 padding 的页面要自己加 `MediaQuery.paddingOf(context).top`），且页面根部 `SafeArea` 必须改成 `top: false`，否则滚动视口被压到标题栏下沿，内容永远钻不过去。（来源：掘金《Flutter 透明模糊化 AppBar 和 BottomNavigationBar 优化方案》的「注意点」）。**④ 渐进模糊（从下到上越来越糊，2026-10-16 补）**：`ui.ImageFilter.blur` 的 σ 是常量、**没有纵向渐变的滤镜**；拿 `ShaderMask` / `Opacity` 去包 `BackdropFilter` 也没用（会引入 saveLayer，backdrop 取样不到，模糊直接消失）。唯一可行的做法是**把标题栏横切成若干条带、每条一个 σ**，边界按整数像素对齐且首尾相接（重叠＝模糊叠加、留缝＝露出一线没糊的），且最下面那条的 σ 要落到 0（否则底部还是硬边）。分带**不等分**：实测 σ>8 之后屏幕上已无肉眼可辨的差别（1px 笔画和 20px 字一样化成一团），所以 σ>8 用粗步长 6、σ<8 用细步长 1（`kImmersiveBlurKnee` / `kImmersiveCoarseSigmaStep` / `kImmersiveFineSigmaStep`），切出约 **10 条**（等 σ 步长硬切要 20 条，每条一次模糊，省的是每帧实打实的开销）；带数只跟「占整条百分之几」有关、**与标题栏高度无关**，每条的 σ 取该带垂直中点处的值（`σ(y)=σ_max·(1-y/h)`）。底色必须跟着模糊一起淡（顶 0.45 → 底 0.10），否则底下那截「已经不糊了」的截面上还盖着底色，看着像玻璃坏了；**Web 没有模糊、底色是唯一分隔手段，因此不淡出**（0.72 平铺）。所有横带共用一个 `BackdropKey`（`BackdropGroup` + `BackdropFilter.grouped`）——引擎只在 `all_filters_equal` 时才复用「一次过滤」，σ 不同时仍各滤各的，但 **backdrop 只读回一次**，省掉十几次全屏翻转；`ImmersiveGlassLayer` 因此从 Stateless 改成 Stateful（key 必须跨 rebuild 保持同一实例，否则每帧换分组＝白做）。**目检手段（可复用）**：写临时用例把滚动态 `matchesGoldenFile` 成 PNG（`--update-goldens`），再用 Pillow 逐行量「竖直黑白硬边」的扩散宽度反推真实 σ（`σ = 幅度/(最大斜率·√(2π))`，注意折 dpr、避开标题文字行），实测与理论线性斜坡吻合。**注意**：标题文字落在距条顶约 73% 处，那里 σ 只剩 ~5，所以别把 σ(y) 曲线调得过凸（如平方衰减），否则标题底下几乎不糊、跟内容打架。
