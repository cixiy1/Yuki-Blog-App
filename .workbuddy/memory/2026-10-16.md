## 沉浸标题栏「封装成公共组件」+ 修掉 Web 上糊满整页（10:30）

- 用户 10:19 发来 Chrome 里 localhost 预览截图：**整个页面糊成一片**、只有标题文字清晰。根因不是我们上一轮的 flexibleSpace 无界高度（那个已修），而是 **Flutter Web 引擎的 BackdropFilter 缺陷**：Web 端画 BackdropFilter 时不对图层做裁剪，滤镜作用到整张 backdrop → 整页糊。症状与「只有标题栏该糊」完全不符，两次反馈都是这个。
- 用户另一条要求：「可以封装成公共的，多处可使用沉浸标题栏」。
- **做法：抽成公共组件（`lib/widgets/`，此前是空目录）**
  - `lib/widgets/immersive_app_bar.dart`：
    - `ImmersiveGlassLayer(progress:, blur:)` —— 材质层（毛玻璃 + 底色 + 顶高光/底发丝两条细线），任何自绘标题栏都能在底层铺它；
    - `ImmersiveAppBar implements PreferredSizeWidget` —— **不再用 `Scaffold.appBar` + `flexibleSpace`**，而是自己实现 PreferredSizeWidget，`preferredSize = Size.fromHeight(kToolbarHeight)`，build 里返回 `SizedBox(height: toolbarHeight + 状态栏高)`，模糊层只能在这条盒子里铺 → 从结构上杜绝「无界高度把模糊撑到全屏」；
    - `immersiveProgressOf(ScrollMetrics)`（原 `glassProgressOf`）+ 常量 `kImmersiveScrollThreshold=50` / `kImmersiveTransition=360ms` / `kImmersiveCurve=(0.22,1,0.36,1)` + Key 常量 `kImmersiveTitleKey / kImmersiveMenuKey / kImmersiveHighlightKey / kImmersiveHairlineKey`。
  - `lib/widgets/immersive_scaffold.dart`：`ImmersiveScaffold(title, body, drawer, actions, leading, fab, bottomNavBar, extendBodyBehindAppBar)` —— 整页骨架，内部用 `GlobalKey<ScaffoldState>` 开抽屉（**比 `Scaffold.of(context)` 稳**，不依赖「context 在 Scaffold 之下」）、`NotificationListener<ScrollNotification>` 换算折叠进度、body 换实例（`!identical`）自动收回贴顶。
  - `HomeShell` 改用 `ImmersiveScaffold`，自带的那套滚动监听 / ValueNotifier / dispose 全删。
  - 删掉私有版 `lib/features/home/widgets/glass_app_bar.dart` 与其测试。
- **Web 兜底**：`ImmersiveGlassLayer.blurSupported = !kIsWeb`；Web 上不铺 BackdropFilter，改「底色加浓到 0.72 + 两条细线」，观感接近但不发散模糊。Android / iOS 走完整配方。
- **左侧按钮取用顺序显式化**：`leading` > `onMenu` > Scaffold 抽屉 > 返回键（`automaticallyImplyLeading`），彻底告别「调用方拿错 context 调 Scaffold.of」那类崩溃。
- **测试 18 项**（`test/immersive_app_bar_test.dart`，替换旧 `glass_app_bar_test.dart`）：两态材质、**回归「模糊层高度 == kToolbarHeight」**、回归「点菜单真能开抽屉」、leading 覆盖、无抽屉不放按钮、进度源刷新、深色、ImmersiveScaffold 四项。**同一套用例在 `flutter test`（真机平台）与 `flutter test --platform chrome`（真 Web 平台）都全绿** —— Web 分支断言 `BackdropFilter` findsNothing，等于在真 Web 上证明了「不会再糊整页」。全量 108 项 + `flutter analyze` 零告警。
- 版本 `1.4.4+13 → 1.4.4+14`（+13 那份已构建并交付过，避免同版本号两个包）；本地提交 `8f4a97e`（feat）/ `6fd8b37`（test）/ `2372072`（release）。**用户 10:30 明确「重新构建，推送」→ 本轮已授权推送 + 打 tag。**
- 教训补充：① 用户报「糊全屏」时先分辨平台——**Web 上的 BackdropFilter 天然糊整页**，限高救不了；② 交付视觉改动仍然必须当场构建 + present_files；③ `flutter test --platform chrome` 是验证 Web 行为的便宜手段，不用起 dev server。
